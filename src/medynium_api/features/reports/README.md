# reports

**Purpose:** A doctor or assistant uploads a patient's report (PDF, PNG or JPEG). It is read in the background and the labs, medicines and diagnoses on it appear as rows, each with its printed date and time, the exact words it came from and the page. A doctor accepts, edits or rejects each row; approval writes the accepted rows to the record, tagged with the report as their source. Nothing read from a report reaches the record before a doctor approves it.
**Endpoints:** POST /patients/{id}/reports (raw body, `X-Filename`); GET /patients/{id}/reports[/{report_id}[/file]]; PUT /patients/{id}/reports/rows/{row_id}; POST .../rows/{row_id}/{accept|reject|reset}; POST /patients/{id}/reports/{report_id}/approve and /reject
**Requirements:** production plan Phase 2 (P2.0 to P2.8); SEC-02, SEC-05, SEC-06; AI-05 (text in a page is data, never instructions)
**How it works:** the file goes to a private encrypted stage (`INTAKE.REPORT_STAGE`), `PARSE_DOCUMENT` reads its pages, a hosted model reads each page into a fixed JSON shape, and `extraction.py` keeps a row only when its quoted words are on the page and its number is in that quote. Confidence is set by code. Dates are read day-first; a missing time is never guessed. The name on the report is compared with the patient: a mismatch blocks approval until a doctor confirms it. Instructions planted in a page are ignored and noted.
**Rules:** an assistant may upload and look; only a doctor decides and approves. A denied patient is audited and answered like a missing one. Files are streamed by the API after an entitlement check and never linked. The type is read from the file's bytes. Size, pages and uploads per hour are capped. Every state is in `CLINICAL.REPORT`, so a restart loses nothing: a sweeper retries a stuck report up to three times. No new dependency: the upload is a raw body, not multipart.
**Limits:** English only; scanned images need legible print; handwriting is not supported. The reading model is a cost-effective hosted one and can miss rows; what it keeps has been checked against the page, what it misses is simply absent (the page text is shown so the doctor can see).
**May import:** `core/` only, never another feature.
**Status:** built; unit tests in `tests/test_reports_extraction.py`, live tests in `tests/integration/test_reports.py`.
