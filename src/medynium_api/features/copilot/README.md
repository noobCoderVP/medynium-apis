# copilot

**Purpose:** Routing, the safety review, route handlers (lookup, changed, analyst, knowledge, drug, panel, refuse), the action allowlist and SSE. Modules: routing, handlers/, panel*, actions, safety, pack, service, repository, ports.
**Endpoints:** POST /copilot/ask, POST /patients/{id}/safety-review, POST /agent/actions
**Requirements:** FR-05, FR-07, FR-18 to FR-21, AI-01 to AI-12, SEC-11, SEC-12; A-1 to A-12
**May import:** `core/` only, never another feature. SQL lives in `repository.py` files (`core/` holds shared SQL helpers).
**Tools now include** `get_attention`, `get_gaps`, `detect_changes` with a 90-day or 1-year window (`handlers/intel.py`, shared rules in `core/intel/`), `read_report` (`handlers/report_reader.py`: the best-matching pages of an uploaded report, cited by page) and `lookup_label_live` (`handlers/live_label.py` via `core/openfda.py`, only when the clinician asks for the live label by name). **Tool registry:** `tools/` names every read tool (`get_patient_record`, `detect_changes`, `query_structured`, `run_safety_review`, `search_labels`, the five panel tools). `tools/resolve.py` maps a routed step to a tool; `service._dispatch` runs it. Handlers are unchanged.
**Drug route:** medicines and options for a condition, with or without a patient open (`handlers/drug_info.py`, prompt `drug_info.md`, answer kind `DRUG`). Chosen by rule (`routing.DRUG_INFO`, or any question on the `knowledge` screen) so it needs no router call. Cortex Search finds the drug's label sections (indications, dosing, contraindications, warnings, adverse reactions, interactions), or for a condition the labels whose indications match; `claude-sonnet-4-6` arranges them into cited statements and `validate_statements(drug_info=True)` drops instructions, rankings and anything unbacked. With a patient open their allergies, medicines, diagnoses and abnormal labs are added so a caution can be tied to a recorded fact (`ai_synthesis`, "may warrant clinician review"). Prescribing questions are therefore answered as documented information, never as an instruction; only a diagnosis is still refused. Needs the `Indications and usage` and `Adverse reactions` chunks (`knowledge/ingest/add_sections.py`).
**Agent route:** a question that needs two or three reads combined (`what changed and is it a concern`, `brief me`). The router (llama3.1-8b, then llama3.3-70b when its plan is unusable) names tools in `params.tools`; `agent_plan.py` validates them against a closed list and their argument models. `tools/compose.py` runs each tool in collect mode (`Run.collector`), renumbers P/S/Q ids, asks `claude-sonnet-4-6` (prompt `composer.md`) for statements over the merged evidence, and the existing validator drops what the evidence does not back. If the model fails, the tools' own statements are shown as found. The short answer is built from what the tools returned.
**Propose route:** the clinician asks to add a note, allergy, diagnosis or medicine, to raise a finding from the previous answer, or to decide on the one open finding. `handlers/propose.py` checks the arguments (free text must come from the question; the manual screen's own models validate the rest) and emits a `proposal` event with a preview. Nothing is saved. `POST /agent/proposals/{id}/approve` (doctors only, own unexpired proposals) calls the real service through `proposal_ports.py` with the proposal id as idempotency key and audits `AGENT_PROPOSED_WRITE`; `/discard` drops it. Proposals live in memory for 15 minutes. Editing or deleting existing records and writing to many patients are still refused by the rule guard.
**Memory:** `last_answer_id` on `POST /copilot/ask` lets the planner see the drug and lab names of the previous answer (closed vocabulary, never free text). **Agent tools run in parallel** (`Run.fork`).
**Panel route:** questions about the clinician's own patients ("who are my patients and what is pending", "which of my patients have low eGFR", "patients like this one"). `panel_plan.py` plans with rules first and the router model second; the plan is validated (closed tool names, whitelisted filters). Five read-only tools: list_my_patients, pending_work, changes_since, patients_matching, similar_patients. Statements carry `patient_id` and `group`. Other doctors' patients and the whole database are still refused.
**Actions:** an agent-planned action stays on the open patient (`actions.py`); the action set is still closed.
**Status:** built. Evaluated by `scripts/eval_golden.py` (golden 19, injection 12) and `scripts/eval_routing.py` (47 cases); results in `docs/quality/` and `docs/evals/`.
