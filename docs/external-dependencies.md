## 4. Snowflake set-up that needs a person

One ACCOUNTADMIN session, run by you after reviewing the SQL (or by me with your approval, using your token for that one run):

- warehouse `MEDYNIUM_WH` (XSMALL, auto-suspend 60 s) and a resource monitor at 50% notify, 80% suspend, against your credit;
- database objects and roles from [../docs/database/README.md](database/README.md) (`MED_ADMIN`, `MED_API`, `MED_DOCTOR`, `MED_ASSISTANT`, `MED_AGENT_READ`);
- the service user `MED_API_SVC` with the public half of its key pair;
- grants for Cortex (`SNOWFLAKE.CORTEX_USER`).

After that I work as `MED_ADMIN`, and you revoke the personal access token. The authentication policy created for the token can be removed with `ALTER USER VAIBHAV143 UNSET AUTHENTICATION POLICY;`.

## 7. Things I will not do

- Put private keys, passwords or tokens in a repo, a log or a chat message.
- Run application code as `ACCOUNTADMIN`. Only the one-off bootstrap needs it.
- Create hosting or GitHub accounts, or pay for plans.
- Treat the personal access token as long-lived: it should be revoked after bootstrap.
